AAA Quick / LoRA 检测引导 1.0-candidate.1
2026-10-23，本地候选工具

用途：排查“生成失败：未配置用于定位基础 MODEL/CLIP 的画风 LoRA 节点”。
只读取选定目录的小型代码、插件配置和 API 工作流，提供对应操作指引。
不修改文件，不更新插件，不改模型、词库或密钥，不提交生图，不结束或启动服务。
无需为了检测先关闭 AstrBot；报告是磁盘状态检查，不证明进程实际加载了哪份模块。

一、怎么打开
1. 完整解压这个 ZIP，双击 AAA-Quick-LoRA-Doctor.exe。
2. 不需要另装 Python。Windows 提示来源不明时，请核对维护者提供的 SHA256；不要关闭安全软件。

二、怎么选目录
懒人包安装：点“浏览”，选择含 Start.cmd、astrbot、hub 的实际安装目录。
例如 D:\QQ-comfyui 或你搬家后的新目录，而不是存放下载 ZIP 的目录。
AstrBot Desktop：点“检测桌面版默认目录”，查找当前用户 .astrbot 数据目录。
自定义安装：可以直接选择含 preset_runtime.py 的 astrbot_plugin_comfy_bridge 目录。
如果找到多份，在“实际插件候选”中手动选择当前 AstrBot 使用的那一份，不能只挑版本号最高的。
如果在目录输入框手填路径，点“重新查找填写的目录”。

三、开始检测
1. 正常情况下会自动定位对应插件配置和工作流，不需要另选 JSON。
2. 工作流不在本机、路径失效或另存位置时，可以手动选择当前实际使用的 API 工作流。
   未读到真实配置时，手选工作流只检查无槽位 dynamic 的结构，报告会明确提示还需核对配置。
3. 点“开始只读检测”，等待状态提示结束。读取进程线索最多等待约15秒。
4. 阅读红色异常、黄色待核对项及最后的处理顺序。
5. 点“导出检测报告”，把 TXT 或窗口结果截图发给维护者。
   报告只输出检测字段、文件位置、模块哈希、节点统计和可识别进程的 PID/程序路径。
   不输出 API Key、Token、完整配置、提示词正文或进程命令行；路径中的用户名可自行遮盖。

四、怎么理解结果
“发现旧版报错分支”：所选磁盘模块仍含旧异常。更新实际运行的 AAA 插件，而不是只更新 App/Hub。
“磁盘包含 Quick 热修分支”：代码文件含无槽位定位逻辑及其调用。单文件热修不会改变版本号。
“基础接线/槽位不匹配”：按当前 API JSON 核对，不要猜填节点编号。
“未找到标准位置的插件配置”：可能选错实例，或者使用其他配置布局，需要人工核对。
“补丁状态无法归类”：其他版本或自定义源码，不能当作没有补丁而盲目覆盖。

对于没有任何 LoRA 节点的 Quick：
加载模式应为 dynamic，画风 LoRA 槽位可以留空；插件动态插入 LoRA。
旧四槽图才使用其真实的 46、47、48、49；不能给九节点图硬填这些数字。
自定义工作流使用实际节点，不要求固定采用 11/12/19；工具优先读取实际配置中的节点 ID。

如果磁盘检查通过，生成仍原样报旧错误：
等任务结束，完整退出对应 AstrBot（包括 Desktop 后台），再重新启动。
确认没有另一套 AstrBot 运行，且补丁没有复制到另一份插件目录。
可参考进程路径，但进程程序路径不能单独证明数据目录；本工具不会把这类线索当作确定结论。

补丁操作前备份真正的插件目录和配置，按相同版本的说明只更新代码。

五、验证边界
识别的是已知源码结构及接线，不验证真实权重文件、LoRA质量、ComfyUI网络或GPU显存。
不启动用户插件、不使用LLM、不需要管理员令牌；进程线索查询失败不影响文件检查。

# 首张图启动向导 1.1（面向电脑新手）

适用项目：AstrAutoAnima 公开版 0.5.0-beta.2。它是**安装完成后的配置助手**，不是新的生图软件或完整环境安装包。

## 怎样打开

### Windows 双击版（推荐给新手）

完整解压 `AstrAutoAnima-FirstRun-Wizard-1.1-Windows.zip`，双击其中 `AstrAutoAnima-FirstRun-Wizard.exe`。本版本已包含运行环境，不需要另装 Python；不需要用管理员身份运行。保留同目录 `docs`，工具内可以直接阅读中文手册。

这是项目本地构建的未签名程序，Windows 可能提示未知发布者。请确认文件来自项目维护者并校验 SHA256；不要为运行程序关闭系统安全软件。遇到企业策略拦截时联系系统管理员，或使用下面的源码方式。

### 源码方式

解压源码工具包。需要 Python 3.10+ 和 Tkinter，不需要 pip 安装其他依赖。

- Windows：双击 `tools/start_first_run_wizard.cmd`。
- 有桌面的 Linux：运行 `sh tools/start_first_run_wizard.sh`。
- 通用：`python tools/first_run_wizard.py`。

**运行位置很重要：** 请在实际安装服务的机器上运行。本向导不提供 SSH/SFTP，不会远程修改云服务器。Windows 上拿 Linux 服务器的配置副本直接保存会被拒绝。无桌面 Linux 可以继续用已有 Admin 在线管理用户／词库，投递目标参考《首次起步指南》配置；本工具暂未提供无桌面远程引导。

## 按九步完成

### ① 找到安装

点“浏览”，选择原安装目录中的 `runtime-env.json`，它通常与 `Start.cmd`／`Start.sh` 在一起。不要选择下载 ZIP，也不要新建空 JSON。

点“读取已有配置”。向导会检查真实插件数据目录，并读取现有投递目标、用户和词库。读取不修改文件。选择后会显示实际数据目录；请确认没有选错另一套安装。

找不到 `runtime-env.json`：先完成懒人包部署。如果是纯手动部署、只有 `.env`，本向导暂不适用，不要为了通过检查伪造空配置。

### ② 连接与授权

1. 现有地址和管理员令牌会自动填入；没有变更就保留。
2. AstrBot 地址通常为同机 `http://127.0.0.1:6185`；ComfyUI 通常为 `http://127.0.0.1:8188`。跨主机按实际可达地址填写。
3. 在 QQ 给机器人发送 `/sid`，复制 Bot ID；不是群号，也不是机器人 QQ。
4. 在 AstrBot 桌面程序或 WebUI → 设置 → OpenAPI 创建 Key，粘贴到“AstrBot API Key”。复制创建成功弹窗中的完整 `abk_` 密钥（已验证的 v4.28.0 为 47 位）；列表中的 12 位前缀不能鉴权。向导会拦截前缀、引号、Bearer 前缀等误填。不要粘贴 Hub 管理员令牌或 WebUI 密码。
5. 管理员令牌已有就不必重新生成。只有缺失或泄漏才点生成，保存并重启后旧令牌失效。
6. 点“暂存连接设置”，再点下一步。

“检查 Hub 是否在线”只做无密钥的健康检查，**不会证明 API Key 正确、QQ 可投递或显卡已能生图**。检测地址只用于检查，不会改变服务监听地址、防火墙或网络配置。

点“验证 AstrBot 完整 Key”并确认目标地址，才会向该服务发送密钥，读取会话列表验证 chat 权限；不生图、不发 QQ。401 是密钥拒绝，403 是权限不足。本机 HTTP / 远端 HTTPS 可用于认证检查，远端明文 HTTP 不发送密钥。不使用系统代理转发密钥，不跟随重定向。

手机上的 `127.0.0.1` 不是服务器地址。远程连接请先配置可信网络、HTTPS／VPN，不能靠改 App 地址就开放原本只监听本机的服务。

### ③ 返图到哪里

填写显示名称、内部 ID、Bot ID、群号或 QQ，选择“群聊／私聊”，点“暂存这个目标”。无需手写 UMO 或 JSON。

- 内部 ID 推荐英文，例如 `test-group`；每个目标不同，不能用 `self-private`。
- 新目标只允许 N。首次用测试群，确认能返图后再调整。
- 点已有行可以编辑或取消启用；修改后仍需点“暂存这个目标”。
- 添加多项时先点“新增空白目标”，避免改到上一项。
- 普通用户的“我的 QQ 私聊”自动绑定其 QQ，无须额外创建。
- Admin 本身没有自动私聊目标；需要时添加一个管理员私聊目标。
- 允许群投递的普通用户会看到全部启用群，不是逐人逐群授权；群目标不支持 S。

### ④ 用户令牌

先给自己添加一个普通用户：填自己的 QQ 和备注，点“暂存新增用户”。默认不允许群投递，只能使用自己的私聊目标；确实需要才勾选群权限。

此时新账号和令牌只在内存中，**没有写入服务器**。最后保存成功后才能领取令牌。已有 QQ 不会被覆盖或自动换发；已有用户的停用、删除和换发使用 Admin 的“用户”页。

建议 Admin 令牌只自己掌握，每个群友使用独立 Service 令牌，不能共享管理员令牌。

### ⑤ 导入词库

点“选择文件并预览导入统计”，选择自己审核过的 JSON，查看新增／更新数量。默认跳过重复 ID，只有想替换相同 ID 时才勾选覆盖。

与当前 App 的追加导入不同，本向导会保留完整自定义分组定义及条目分组。当前配套编辑器面向 B/G/D/C/R 基础来源；不支持的专用格式会停止导入，不会静默删条目。

没有词库可先跳过：普通英文生图不需要词库。需要制作词库时，点“打开配套词库编辑器”，在工作副本上维护，保存后回到向导导入。不要在向导开着时同时改运行文件；发生并发修改会要求重新读取。

### ⑥ 角色词典（可选）

- 已有词典：选择包含 `characters` 数组的 JSON，验证后暂存；不是导入随机池或 LoRA。
- 没有词典：点“确认来源后在线装配”，确认公开来源和许可后才下载；成功后显示数量，不立即覆盖运行文件。公网失败不会破坏旧词典。
- 来源为 [tcpassos 角色结构](https://github.com/tcpassos/mcp-danbooru-characters) 和 [ffdkj 中文翻译表](https://github.com/ffdkj/ffdkj-Danbooru_Tag-Chinese-English-Translation-Table)。下载数据不随本包分发；使用和再分发需自行核对数据来源许可，不能将项目代码许可套用于第三方数据。
- 第 ⑦ 页保存后，在 AAA 插件设置中启用中文角色名词典并核对词典路径与向导显示路径一致。App 刷新“角色词典”，搜索名字，先使用弱模式；强模式额外加入外貌词。
- 替换主词典会备份原文件；不会删除 `character_dictionary_edits.json`、收藏、LoRA 或预设。词典有该名字，不代表 Anima 底模一定能准确画出这个角色。

### ⑦ 确认保存

1. 暂停其他管理员编辑和群友任务。
2. 点“刷新变更预览”，核对每个将修改的文件路径，预览不显示密钥。
3. 勾选确认，再点“确认保存并备份”，并确认弹窗。
4. 原文件备份放在同目录，文件名含 `.backup_first_run_`；新文件无需备份。
5. 点“领取新用户令牌”，选择用户，复制令牌私发，或导出到新的私密 CSV。关闭程序后无法从哈希恢复令牌；明文不要截屏发群、公开上传或写进日志。
6. 修改连接字段后，正常停止并重新启动实际 Hub。**双击 Start 会复用旧进程，不等于重启。** 程序不会擅自强杀或重启任何服务。

单个文件采用备份和原子替换；多个文件不是数据库事务。如果磁盘／权限问题导致中途失败，弹窗会列出已保存项目，后面的文件不会继续写入。先检查状态与备份，不要盲目反复点击。备份也可能含凭据，需私密保管；Windows 继承所在目录权限，Linux 新配置／备份按当前用户读写权限保存。

### ⑧ 首张图

完整操作见同包 [首张图逐项操作](FIRST_IMAGE_WALKTHROUGH.md)，也可在第 ⑨ 页直接打开阅读。

1. 先在 AAA 插件配置页核对普通 API 工作流、正负提示词节点和模型；batch_size 设为 1。
2. 选择这个实际使用的 API 工作流文件，点“检查节点 / 模型名称 / GPU”。检查是只读，不会自动替换缺失模型；通过也不等于权重完整或显存够用。
3. 点“读取目标”，确认向哪个 Hub 发送管理员令牌。出现目标证明 Hub 的管理员授权已通过。
4. 选择自己的测试目标。默认不投递 QQ；首次只验证图片返回，勾选 QQ 时会再次提示具体目标。
5. 点“提交测试图”，阅读确认弹窗。它通过原有 Hub API 提交普通英文任务，不选角色、画风、HQ、反推、五连抽。不需要中文 LLM 或随机库。
6. 点“查询 / 取图”。排队和运行状态可稍后再次查询，不用重新提交；成功后取回第一张图片并校验大小和 SHA256。
7. 支持尺寸范围内的 PNG 可直接预览；JPEG/WebP 或过大 PNG 请另存后用系统看图程序打开。另存不覆盖已有文件。
8. 关闭向导不会取消后台任务。可在 App“记录”找到任务 ID，填回向导恢复查询。提交超时先查记录，不能把超时当成“没有生成”。

**首张图通过不等于 QQ 到达或所有用户有权限。** 还要用 Service 的个人令牌验收私聊，再显式测试群投递。失败不输出含凭据的原始响应，在 App 记录及本机日志按任务 ID 排查。

### ⑨ 工具与帮助

界面可直接打开离线中文说明、词库编辑器和用户令牌管理器。也可确认后打开 AstrBot / ComfyUI / Hub 的浏览器界面，URL 不携带任何密钥。

## Service 客户端与 QQ 的最后验收

1. Admin 填 Hub 地址和管理员令牌，应能进入“用户／提示词”等页面。
2. Service 填相同地址和刚领取的普通令牌。
3. 选择“我的 QQ 私聊”，直接英文生图，不选 LoRA、HQ、反推或五连抽。
4. 在 App“记录”看到图片，再测试“生成后发送到 QQ”。
5. 需要本地下载时开启“生成完成后自动保存到本地”，在“更改保存目录”中选择可写目录。
6. 导入词库后再测试 B/N 的“来张好图”。

无显卡时可以先完成配置，但不能因此宣称生图通过。更详细的字段含义和故障检查见同包《FIRST_RUN.md》。

## 本版安全边界

- 加载、切换页面和取消操作不写入运行配置。
- 不上传你的配置，不搜集密钥，不自带真实词库或令牌。
- 无操作时不下载、不改端口／防火墙、不发消息、不启动训练。公开数据下载、认证请求和生图需单独确认；QQ 投递默认关闭并需显式选择。
- 不自动重置旧用户令牌；新增用户默认关闭群投递。
- 拒绝不存在的数据目录、跨系统路径、符号链接／目录联接和冲突修改。
- 文件变更必须在最后确认。令牌不会出现在概要和健康检测结果中。
- 此版本是新增配置辅助工具，不会替换已有 0.5.0-beta.2 的客户端、Hub 或插件。
- 本次自动化覆盖本机模拟 HTTP 的鉴权 / 提交 / 查任务 / 图片校验及 Windows EXE 启动；未把这些测试冒充真实 GPU、真实 QQ 账号的端到端验收。最终验收以用户实际返回图片和 QQ 收件为准。

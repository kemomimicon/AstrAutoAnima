# 从安装完成到第一张图：新手逐项操作

使用配套首张图向导 1.1。它不会替你登录 QQ、接受第三方许可或付费开 GPU。
已有服务无需重新安装；每一步通过后再进入下一步。先完成普通图，后做角色、随机库和高级工作流。

## A. 打开正确的服务

1. Windows 已有 AstrBot Desktop：正常打开原桌面程序，确认 AAA 插件与 Anima Master **0.7.1** 加载成功，不再安装第二份 AstrBot。
2. 启动实际 ComfyUI 和 Hub。懒人包使用原安装目录 `Start.cmd`；Linux 按原服务管理方式启动。
3. 在向导选择同一目录的 `runtime-env.json`。看到的数据目录应当属于实际 AstrBot，不是下载 ZIP 或桌面程序的 exe 安装目录。
4. 修改连接后需要重启 Hub。再次双击 Start 只会复用旧进程；退出 App 也不会退出 Hub。使用原服务管理方式正常停止后启动，不要在任务管理器中批量结束所有 Python。
5. 不知道如何停止哪一个后台时先保留现状，提供服务启动方式求助；不要反复开第二份或删除目录。

## B. 基础模型三件套

在向导第 ⑨ 页打开“Anima Master 0.7.1 配置指引”，其中列出官方模型下载链接、许可和目录。
默认 Anima Base 1.0：

| 文件 | 放到实际 ComfyUI 下 |
| --- | --- |
| anima-base-v1.0.safetensors | models/diffusion_models/ |
| qwen_3_06b_base.safetensors | models/text_encoders/ |
| qwen_image_vae.safetensors | models/vae/ |

模型不在启动向导 ZIP 中。原部署器勾选三件套并同意许可后才会下载和按哈希校验；已经有文件就不要重下。
手动下载后刷新或正常重启 ComfyUI，让加载节点列表出现真实文件名。不要重命名其他模型冒充这三个文件。
需要官方地址时阅读 [模型与 AM 指引](ANIMA_MASTER.md)。此启动向导本身不下载几 GB 权重、不升级 Torch、不安装驱动。

## C. 对齐 AAA 和 AM 的工作流

1. 使用部署器生成的 `AAA_Quick_Local_api.json` 做第一张图；若部署时未选模型，这个文件可能尚未生成，不要伪造空 JSON。
2. 或在 ComfyUI 打开自己已验证的普通文生图工作流，在加载 UNET / CLIP / VAE 节点选择实际模型。把空 Latent 的 batch_size 设为 1；先不要加载私人 LoRA 或 HQ/Refine 模型。
3. 导出 **API 格式** JSON。普通编辑器 JSON 的 `nodes` 数组不是 AAA 所需的 API 图。
4. AstrBot → AAA 桥接插件配置：核对 ComfyUI 地址、`workflow_path`、正面提示词节点 ID、负面提示词节点 ID、采样器 ID。ID 来自你的工作流，不能抄别人截图里的数字。
5. 正面提示词节点应存在 `inputs.text`，并连接到实际采样器正面条件。模型路径和节点 ID 不对时先修正，不要靠改群号解决。
6. Anima Master 使用 **0.7.1**；按 AM 指引配置同一个 ComfyUI 和自定义工作流，不开重复自动拉起。上游 0.9.1 未完成本项目联调；不自动升级。两插件的重名指令应避免同时处理。
7. 向导第 ⑧ 页选择 AAA 实际配置的 API JSON，点击只读检查。它会列出缺节点和不在 ComfyUI 枚举列表中的模型名称。不能证明大模型文件未损坏，也不能替你修正插件里选错的 workflow_path。

## D. Key、目标和首次普通图

1. AstrBot 程序内 设置 → OpenAPI，新建 Key（chat/file/im）。创建弹窗的完整 `abk_` Key 才有效；列表的 12 位前缀不能使用。不要填 QQ 密码、NapCat token、Hub token 或 LLM API key。
2. 第 ② 页粘贴 Key，点击只读鉴权检测。401 先查完整 Key；403 查权限。密钥不要截图发送。
3. QQ 给机器人发 `/sid`，复制真实平台 Bot ID。第 ③ 页添加自己的私聊测试目标或测试群；不要猜 Bot ID 等于 QQ 号。
4. 第 ⑦ 页保存并备份，若连接变化则正常重启 Hub。
5. 第 ⑧ 页读取目标并选择；默认不勾选 QQ 投递。提交一次测试英文图，之后点击“查询 / 取图”直到结束。网络超时先在 App 记录查重。
6. 看到“图片取回、大小与 SHA256 校验通过”后预览、另存。只有任务进入队列、健康检查通过、终端无报错，都不算完成。
7. 在 Service App 填 Hub 地址和自己的普通令牌，再生成一张普通图，查看历史和本地保存。最后才打开 QQ 投递并确认收件人真实收到。

## E. 装配角色词典

向导第 ⑥ 页可导入现有词典或确认来源后在线装配。在线数据只用于角色结构与中文译名，不下载 LoRA、不包含作者 OC、私人随机库或密钥。
装配后在第 ⑦ 页确认主词典路径并保存；原主词典自动备份，edits/收藏/预设不被覆盖。
AAA 插件开启中文角色名词典，并将其路径与向导显示路径对齐。App 刷新角色词典，搜索名字，先选弱模式测试。
弱模式主要使用角色标签；强模式增加词典里的外貌词，可能与用户服装等提示产生冲突。
没有匹配时核对别名和词典路径，不要把随机提示词 JSON 当词典导入。底模不认识的角色仍可能需要角色 LoRA。

## F. 后续工具按目的选择

| 想做什么 | 在向导哪里操作 | 完成标准 |
| --- | --- | --- |
| 给自己/群友账号 | ④ 用户 → ⑦ 保存 → 领取令牌 | 每人自己的 Service 能登录，明文只私发 |
| 批量删改提示词 | ⑤ 打开词库编辑器 | 工作副本保存、重新打开验证后导入 |
| 自定义随机分组 | 词库编辑器“管理自定义分组” | 条目加入分组，先试 N 级调用 |
| 按组复制导出 | 词库编辑器筛选后导出 JSON/CSV | 明确“筛选结果”不是全库备份 |
| 批量发账号/换发令牌 | ⑨ 离线用户令牌管理器，或 Admin 用户页 | 已有注册表先备份，换发后旧令牌失效 |
| 管理角色/画风 LoRA | Admin 的角色/画风预设页 | 文件存在，触发词和强度单独验证 |
| 保存到本地 | ⑧ 另存首张图；日常使用 App 自动保存 | 确认文件在客户端而非服务器，目录可写 |

完整输入输出、并发修改风险与操作顺序见 [工具说明](TOOLS.md)。第一次不要同时启用全部高级功能。

## G. 失败时按层排查

- AstrBot 401：不是 GPU 问题；先排除 12 位前缀、过期/撤销 Key、错误实例。不要重装模型。
- Hub 401：检查 Hub 管理员令牌；与 AstrBot Key 是两种凭据。
- 配置检测成功但任务仍 AstrBot 401：Hub 可能没重启或用另一份 runtime-env.json。
- 目标为空：配置未保存、未启用或令牌权限不允许；读取的是当前运行 Hub，不是向导内暂存数据。
- ComfyUI 连接失败：服务未启动/地址错误；不能靠开放全部端口修复。
- 缺模型/节点：在实际 ComfyUI 安装对应组件，刷新后检查；先不要启动 HQ/反推。
- 显存不足：降低分辨率，batch_size 保持 1，停止其他占显存任务；不保证所有 GPU 支持当前图。
- 任务成功但无图片：不是验收成功；检查保存图片节点和 AstrBot 插件返回链路。
- 向导图片成功但 QQ 没收到：先确认是否勾选投递，再查 NapCat 登录、Bot ID、QQ/群号与平台连接；客户端图片成功不能替代 QQ 到达确认。

求助只发版本、HTTP 状态、任务 ID 和脱敏错误。不要上传 runtime-env.json、.env、令牌 CSV、登录二维码或整套私人数据目录。

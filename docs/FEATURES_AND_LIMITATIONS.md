# 特色、优点与限制

## 特色

- 从 QQ 指令到 ComfyUI 回图的完整闭环，并区分群聊与私聊来源。
- 角色、画风、提示词、画布、采样器和工作流 Profile 都可结构化控制。
- Quick、HQ、Refine、Reverse、Training 按 Workflow Registry 分离，方便逐步替换工作流。
- 随机库同时有兼容来源、安全标签与任意自定义分组，支持显式 S 组和 OC 保护回退。
- 反推不是单一 caption：WD/CL 标签与 JoyCaption 通过 compiler 分类整合，并保留原始结果。
- Hub 令牌按用户绑定，客户端能够提交任务、查看历史和保存图片。
- 本地工具可离线批量维护提示词、自定义分组与令牌，不需要登录服务器 WebUI。
- 一键部署助手默认离线、先预检再备份；外部下载与依赖修改必须逐项启用。

## 优点

- 模块边界清楚：QQ 接入、工作流执行、远程管理互相可替换。
- API 工作流可审计，失败时能查看实际提交节点而不是猜测。
- 预设和提示词库独立持久化，插件升级不应覆盖用户数据。
- 服务器与 Windows 本地部署均可用；Android 只作为客户端，不承担模型计算。
- 公开包默认空库、通用客户端素材和占位模型，降低误泄漏私人素材的风险。

## 缺点与已知限制

- 安装链较长，AstrBot、NapCat、ComfyUI、外部节点、模型和 Hub 任一层都可能影响结果。
- 节点 ID 与 API 工作流拓扑存在耦合；用户改图后必须同步配置/Registry。
- HQ、Refine、反推和训练仍为 Beta，尚未覆盖所有自定义节点组合。
- 四个画风 LoRA 槽仍是当前兼容基线；改成 LoRA Stack 需要同步改写运行时节点映射。
- `/aicn` 依赖单独的 AstrBot LLM Provider，不是开箱即用的离线翻译。
- CL Tagger 模型可能需要授权，JoyCaption 与 ONNX/GPU 依赖对环境版本敏感。
- N/H/S 自动分级可能误判，不能代替人工审核、平台政策或年龄保护。
- 多人图分流、远程工作流/LoRA 一键安装等仍属于后续规划。
- Anima Master 仅验证 0.7.2；0.8.0 的配置、命令和兼容性未知。

## 不适合的场景

- 不受控地向公网开放匿名生图。
- 未经授权使用他人 OC、LoRA、图片或受限模型。
- 把内容分级器当作法律/平台合规保证。
- 无备份地直接在唯一生产实例升级全部组件。

# AutoDL 公开镜像发布检查表

本检查表用于把私有保存镜像整理成可公开申请的候选。当前只准备本地仓库材料，
不操作原实例、已保存镜像或计费资源；不代表已经推送 GitHub 或提交平台审核。

该远端运行时仍为 `0.5.0-beta.2`。本次只新增检查工具和材料，不覆盖既有功能补丁。


旧版发布包不能充当 build44 镜像对应源码。公开前需将候选实际包含的自有源码、
第三方对应源码/许可证和固定版本清单按其授权准备好，并记录对应的公开提交或来源包。
不能只在旧 main 加一份 README 就宣称整个镜像源码已经同步。

## 本地准备

- [x] 独立分支，保留原工作区和服务器不动。
- [x] 使用说明、SSH/凭据对照、模型与词库边界。
- [x] CPU 标准库只读检查脚本、本地单元测试、独立 CI 配置。
- [x] 第三方来源/再分发核对表和机器可读的待验收清单。
- [ ] 审阅后再推送；本轮不推送或创建公开发布。

在仓库根目录运行以下本地检查，无需显卡：

```bash
python3 -B -m unittest discover -s tools/tests -p 'test_autodl_image*.py' -v
python3 -B scripts/check_autodl_image_materials.py
python3 -B scripts/privacy_scan.py .
```

上述材料检查通过不改变验收清单。CI 在 3.11/3.12 上只验证材料和脚本，不启动镜像；
GitHub CI 必须在推送后另看结果，不能以本地测试代称远端 Actions 成功。

## 只读服务器检查

只有用户另行选择了独立测试实例后才操作；无卡模式也可能计费，不能擅自开机。
检查实例身份、磁盘和封存载荷；不要运行恢复启动器，不登录 QQ，不改变密钥。
`public_probe.py` 可显式校验大载荷 SHA，但不会解压或判断整个镜像已经脱敏。
不要为省事重置系统、更换镜像、强杀服务或删除已有目录。

AutoDL Art 发布表单要求 `/root` 下有对应 Git 仓库，并能执行仓库中简单代码。
应在未来的发布候选中验证 `/root/AstrAutoAnima` 的来源和固定提交；
结构脚本只是一个可执行检查入口，平台是否认可须以实际审核为准。
本次材料没有修改原镜像的 `/root`、旧 `/ws` 说明或封存载荷。

## 有卡后逐项验收

1. 从私有镜像创建独立实例和新数据盘，确认自己的 SSH/Jupyter 入口可用。
2. 验证平台身份与应用凭据不沿用提供者；两次独立初始化的应用凭据不同。
3. 完整载荷 SHA、恢复路径和实际运行版本正确；不以控制台原基础镜像字段代替。
4. AstrBot 初始登录、改密、正常重启后登录；分别检查 Hub/NapCat/OneBot 用途。
5. 基础英文首图、OpenAPI、QQ 私聊/测试群投递、新任务的回复关联。
6. 管理端恢复连接、词库/角色字典、客户端预览/下载及个人保存。
7. Studio 只做健康、模型与字典可见性测试，不自动训练。
8. SeedVR2 选装后单独推理；JoyCaption 未安装则保留“不提供”，不冒充成功。

将脱敏结果填入 `examples/autodl_image_acceptance.pending.json` 的副本，并关联证据编号。
不要把密码、聊天内容或含登录信息的截图当成公开验收附件；未知项写 pending，不猜测通过。

## 公开母版与提交

验收实例会写入新凭据、QQ 登录态和用户记录，不能直接把它再次打包公开。
应在干净的发布候选分支补入对应仓库、修正 `/ws` 说明、保留源码/许可证，再重新脱敏和保存；
保留当前已成功保存的镜像作为候选历史，不覆盖它。新候选还要单独恢复验证。

提交前全部满足：

- 新实例恢复与首图验收通过，未提供的能力明确排除。
- 隐私检查覆盖载荷和主机，不仅扫描 Git 仓库；平台凭据初始化经验证。
- build44 源码/二进制/工作流与公开来源逐项对应。
- 再分发清单没有待核对项，必要许可证、修改说明、对应源码已提供。
- 发布文案、启动入口、资源清单与实际镜像一致，已填写最终公开提交和镜像版本。
- 用户明确要求提交，才进行平台导入/发布，不自动申请或承诺审核结果。

## 先选对入口：你现在属于哪一种

| 当前情况 | 打开什么 | 接下来做什么 |
| --- | --- | --- |
| 从未部署 AAA | 对应系统的 `Deploy-Windows.cmd` / `Deploy-Linux.sh` | 选择目录、已有或新环境、需要的模型，先预检，再确认部署 |
| 部署中途失败、断网或关窗 | 同一个部署器 →“载入上次填写” | 选原安装目录的 `last-plan.json`，修正原因后重试；不要换新目录下载第二份 |
| 已装好，今天只是开机使用 | 安装目录的 `Start.cmd` / `Start.sh`，或部署器“仅启动已有服务” | 不安装、不下载、不换令牌；Desktop 需手动打开 |
| 服务能打开，但还没设置收图和授权 | “打开首次配置向导”或独立首张图向导 | 读取 `runtime-env.json`，完成授权、自己的私聊目标、保存、首图验收 |
| 以前正常，现在报错 | 首张图向导 →“故障恢复（不重装）” | 找对应症状；保留配置、日志、模型和更新前备份 |
| 安装在下载目录，或改名/移动后路径不存在 | Windows 安装中心⑥或独立搬家工具 | 关闭服务；没搬用“搬家”，已搬用“就地修复”；保留原目录，不换令牌 |
| 已能出图，准备增加功能 | 安装中心⑤，或首图向导⑨ →“扩展装配” | 先读状态和前置条件；按需预选，逐项安装、配置、验收，不全选 |

两个目录要一直记住：**包的解压目录**放安装工具；**独立安装目录**放运行文件、`Start`、配置和日志。以后启动用后者，不是反复运行安装器。已有 AstrBot / ComfyUI 数据可能在第三个位置，以向导最后确认的实际路径为准。

首次推荐只走最短路径：**Quick 普通英文单图 → 客户端 → QQ 投递 → 词库／角色 → HQ／反推**。随机库、角色词典、反推大模型都不是第一张基础图的必需条件。需要人工完成的 QQ 登录、许可证确认、API 授权不能假装自动完成。

网络修订版 `0.5.0-beta.2-network.1`：遇 Hugging Face 超时或 Windows `0x80092013`，先看 [下载方式选择与本地导入](DOWNLOAD_NETWORK.md)。新包仍使用 beta.2 的组件版本，不要求重装已正常工作的服务。

## 能自动完成什么

本包不是只复制文件：选择目录和选项后，一次点击完成预检、独立 Python 环境、所选依赖安装、插件 / 节点安装、配置和随机管理员令牌生成、服务启动与健康检查。以后用安装目录的 `Start.cmd`（Windows）或 `Start.sh`（Linux）启动。

不偷偷替用户做的事情：安装显卡驱动、接受模型许可证、下载未勾选模型、登录 QQ、绕过 AstrBot API 授权、修改系统防火墙或公开端口。没有模型或授权时，程序会明确报告“待配置”，不是宣称生图已可用。本 Beta 尚不承诺所有全新 Windows/Linux、显卡和第三方节点组合均可无人值守安装。

首次外部下载可能数 GB；建议先完成 Quick，再逐项启用反推与放大。已有环境只接入，不更换其 PyTorch。NapCat 引导准备已校验的官方安装入口，由用户确认执行上游安装器；不操作登录缓存，不保证下游安装器无需人工确认。

## Windows：首次部署

先选择对应系统的包：[Windows 分步指引](DEPLOY_WINDOWS.md) / [Linux 分步指引](DEPLOY_LINUX.md)。AstrBot Desktop 与 CLI 必须选择正确模式；桌面版无需填写内置 Python。

1. 下载并完整解压 `AstrAutoAnima-lazy-bundle-windows-0.5.0-beta.2.zip`。不要在 ZIP 内运行。
2. 双击 `Deploy-Windows.cmd`。缺 Python 3.12 时会询问是否用 winget 安装官方 Python；缺 Git 时也单独询问。拒绝则不下载。候选新版先显示安装与启动中心，选择①进入环境部署。
3. 选择一个**空的独立安装目录**，例如 `D:\AAA-install`，不要选择磁盘根目录、用户目录或 ZIP 解压目录内部。
4. 二选一：
   - 已有环境：填写 AstrBot 根目录（包含 `data`）、ComfyUI 根目录及其 Python 可执行文件。venv 的 Python 通常在 `.venv\Scripts\python.exe`。
   - 全新环境：勾选下载 AstrBot 4.27.2、ComfyUI v0.21.1。会安装到独立目录，不覆盖其他实例。
5. 首次安装勾选“允许安装依赖”。NVIDIA 环境保留 GPU 选项，须已安装兼容驱动；CPU 选项仅适合安装验证，实际生图可能非常慢。不支持自动选择 AMD/Intel 计算后端，请接入已配置好的 ComfyUI。
6. 选择本地 UNET、CLIP、VAE，或勾选下载默认 **Anima Base 1.0** 三件套并确认许可。会按哈希校验并自动放置，生成不含私人 LoRA 的 Quick API 工作流。勾选核心上游 **Anima Master 0.7.1**，按 [AM 配置说明](ANIMA_MASTER.md) 完成联通。
7. 如果已有 AstrBot OpenAPI Key / 平台 Bot ID，一并填写；否则可稍后填写。**Bot ID 不是用户 QQ 或群号。**
8. 按需勾选反推 / 放大节点与模型下载，默认全部关闭。
9. 候选新版先点“① 只做预检（不安装）”，纠正提示后再点“② 确认部署 / 修正后重试”；旧版对应“预检并一键部署 / 启动”。确认窗口会列出真实目录，请逐项核对。部署时请勿关闭窗口；失败时保留文件，不强杀服务、不清空安装。

不要同时运行旧实例：6185 / 8188 / 6278 被占用时，部署会停止，防止边运行边覆盖。

## 第一次联通

- AstrBot：打开 `http://127.0.0.1:6185`。首次密码查看安装目录 `AstrBot.log`，按上游提示修改。
- ComfyUI：打开 `http://127.0.0.1:8188`；健康接口 `/system_stats` 应返回 JSON。
- Hub：访问 `http://127.0.0.1:6278/api/v1/health` 应显示 `0.5.0-beta.2` 和 `ok`。附带 Web App 的懒人包会自动配置首页；纯源码 / 服务包没有 Web App 时根页面 404 不代表服务未启动。
- App：填写 Hub 地址和安装目录 `runtime-env.json` 中的 `AAH_ADMIN_TOKEN`。不要把这个文件发到群里或提交 Git。
- AstrBot API：在 WebUI `设置 → OpenAPI` 创建所需 API Key，授予实际使用接口的 chat / message 等权限，再用向导填写 Key 和 Bot ID。向导不会自行改写 AstrBot 的内部密钥数据库。
- QQ：安装与启动中心②，或首次配置向导⑨打开 NapCat 引导。新安装准备官方入口；已有安装跳过。自行扫码，设置反向 WebSocket 客户端与一致的 OneBot Token，用日志和 `/sid` 验收；只打开6099页面不算接通。已有配置不改写。
- 中文生图 `/aicn` 仍需可用 LLM Provider，不会凭空提供免费翻译 API。反推模型、普通生图与 LLM API 是不同依赖。

修改授权、投递和词库优先用首次配置向导，不必重新部署。补外部节点/模型用扩展中心“仅补装扩展”，不要重跑整套部署。确需更新AAA项目代码时，使用匹配的更新包并备份后停服；版本门禁拒绝覆盖时不要删除版本文件绕过。既有令牌、配置、用户提示词不会自动重置；完整部署中显式填写的新 API Key / Bot ID 会更新 Hub 的对应值。已有工作流路径请在 AstrBot 插件设置中修改。

## 失败后继续：不要从头删除重装

候选新版在耗时操作开始前保存 `last-plan.json`（不含 API Key），同时记录 `deployment-status.json`。后者只描述上次做到哪里，**不是盲目信任的成功凭证**。

1. 看最后的“步骤 X/9”和错误。若旧窗口仍在下载／安装，先等待，不同时开第二个安装器。
2. 重新打开部署器，点“载入上次填写”，选择**原独立安装目录**的 `last-plan.json`。默认路径可能不是你的原目录，必须确认。
3. 读取只填表，不执行。API Key 框会空白：已写入 `runtime-env.json` 的 Key 保留；第一次尚未保存时需要重新填写，也可先空着完成部署后再配置。
4. 改正网络、路径等问题，重新点“只做预检”，再确认重试。会重新检查步骤，并复用完整模型与正常断点；部分 pip 检查、源码备份／复制会再次执行，不承诺直接跳到失败命令。
5. 如果已经生成 `Start`、`runtime-env.json` 和 `services.json`，且只是第9步服务未就绪，先看各服务日志，用“仅启动已有服务”继续，**不要先重跑完整部署**。
6. 向导说“文件部署完成”以后还要做首次配置与首张图验收。`下一步.txt`、健康接口、图片取回分别证明不同阶段，不能互相替代。

| 停在哪里 | 成功标准 / 应做什么 | 不要做什么 |
| --- | --- | --- |
| 预检：目录错误 | 选真实数据根；Desktop 模式不填内置 Python | 新建空 data 冒充环境、把 models 当 ComfyUI 根目录 |
| 步骤1：端口占用 | 先正常关闭正在使用的服务，再安装；若只是使用服务则直接打开客户端 | 强杀不明 Python 进程、重复启动第二套后端 |
| 步骤2/4：pip 或 Git 失败 | 网络恢复后用同一计划重试；保存具体错误。若残留非空 Git 目录阻止 clone，交维护者核查 | 删除整个安装目录、盲目升级原环境 Torch |
| 步骤5/6：模型下载失败 | 用下载说明选镜像／代理／本地；检查磁盘，保留 .part | 关闭 SHA256、把网页改名成模型、重复下载到多个目录 |
| 步骤7：权限、路径或 AM 失败 | 看实际路径及 AM 版本；使用 0.7.1 基线，不自动降级已有版本 | 把他人的 runtime-env.json 拿来覆盖 |
| 步骤9：服务未就绪 | 看安装目录的 Hub.log / ComfyUI.log / AstrBot.log；Desktop 看自身日志 | 以“进程存在”当成可用，或把“仅启动”当成重启 |
| 首图：401 / 无模型 / 无图片 | 到首张图向导对应页检查 Key、工作流、任务记录 | 重置全部令牌、反复提交同一个图像任务 |

## 填错了如何重置

- **部署器“重置某组填写”**：只改当前表单，可重选环境路径、本地模型、网络方式或取消外部下载勾选；保留独立安装目录。不会卸载或删除任何东西。取消勾选也不会卸载之前安装的组件。
- **首次配置向导“撤销本页修改”**：只恢复本页到最近读取／保存的内容，不影响别页；第②～⑥页可用。新增未保存用户的暂存令牌会清除，已经保存的用户不受影响。
- **“重新读取已有配置”**：重新读磁盘，会放弃暂存内容；先领取本轮已经生成并保存的用户令牌。不会恢复出厂。
- **已经保存错了**：撤销按钮不回滚磁盘。能打开向导时改正对应项再确认保存（自动备份）；无法载入时先看故障恢复，确认实际目录及对应 `.backup_first_run_` 文件。备份可能有密钥，不发群，不整目录盲目覆盖。
- **测试图超时**：先按任务 ID 查询或查看 App 记录。只有确定旧任务结束后才点“旧任务结束后新一轮”；这不是取消任务按钮，也不会清空服务器历史。

不提供“清空整个安装／恢复出厂”按钮，以免把问题修复变成数据丢失。

用 `/aimg_status` 检查插件后先跑一张普通图。HQ / Refine / SeedVR2 的模板仍有 `YOUR_*` 占位符；请按 `docs/WORKFLOWS.md` 选择所需节点、模型和参数，不能把仅部署文件当作全部高级工作流已经验收。

## Linux / 无图形服务器

准备 Python 3.12+（全新 AstrBot）、venv 和 Git。有桌面时可执行 `sh 一键部署_AstrAutoAnima.sh` 打开同一个向导。无桌面不要调用 Tk 窗口：

1. 复制 `examples/deployment-plan.linux.json` 为自己的计划，修改安装目录和已有环境路径。
2. 首次安装将 `install_dependencies` 设为 `true`；全新环境再按需设 `install_astrbot` / `install_comfyui` 为 `true`。
3. 计划可填写模型本地路径；API Key 可以先留空。包含密钥的计划文件必须妥善保护，勿发布。

```bash
python3 tools/deploy_project.py --plan /path/to/my-plan.json
python3 tools/deploy_project.py --plan /path/to/my-plan.json --apply
```

第一条仅预检，不写文件、不联网。第二条安装并启动。之后运行安装目录的 `Start.sh`，不是反复运行完整安装。

全新环境下载固定 AstrBot 4.27.2 / ComfyUI v0.21.1；Python 第三方依赖会由 pip 解析，不是全离线镜像。网络代理请用系统正常配置，不要在 URL 中嵌入账号密钥。

## 安全、备份和升级

- 默认 Hub 和 ComfyUI 只监听回环地址；手机或远程客户端应通过自己配置的 HTTPS / VPN。不要裸露 QQ、ComfyUI 或 AstrBot 管理端口。
- 文件升级前在安装目录 `backup_时间_随机值` 保存项目源码及插件配置；用户运行数据不会被发布包替换。首次旧版升级仍建议独立备份 AstrBot data。
- 候选新版使用操作系统锁 `.deploy-session.download.lock`，进程退出自动释放；小锁文件保留属正常，不需要删除。若遇旧版遗留 `.deploy.lock`，新版会停下；先确认旧安装器已退出，再按维护者指导只处理这个旧标记，不清理模型或配置目录。
- `runtime-env.json` 是本地凭据；Linux 权限为 600，Windows 使用账户目录 ACL。`last-plan.json` 不保存 API Key。
- 日志和备份可能含用户后续配置，应留在本机，不要当发布资产上传。
- 不自动配置系统级开机自启；可把 `Start` 入口交给自己的服务管理器。不要给陌生用户系统关机或重启权限。
- 原有 `tools/easy_installer.py` 仍可用于专业用户只部署文件；新版默认入口是 `tools/deploy_project.py`。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 无 Python / Tkinter | Windows 按提示安装官方 Python 3.12（含 Tcl/Tk）；Linux 用计划文件 CLI 或安装系统 python3-tk |
| 目标目录非空 | 使用新空目录；接入已有服务时填写已有环境字段，不要把它们当向导安装目录 |
| pip / Git 下载失败 | 查网络、代理和日志，保留现有目录重试，不要删除配置或模型 |
| CUDA 不可用 | 先核对显卡驱动；CPU 仅验证服务，不能保证跑图速度；不自动卸载旧 Torch |
| 有进程但服务未就绪 | 以健康接口和日志为准，不以 screen 名或进程存在作为成功标志 |
| 反推缺节点 / llama_cpp 失败 | 查节点 requirements、GGUF/mmproj 配对与 GPU 后端；本向导不保证可自动编译所有平台的 llama-cpp CUDA |
| Hub 401 / 403 | 核对本机新生成令牌、普通用户权限及 AstrBot API scope，不使用作者服务器的令牌 |
| 随机抽不到提示词 | 公共包是空库，先导入自己的内容。可用本地提示词编辑器创建任意自定义组 |
| 第一次就能打开页面但不能跑图 | 阅读安装目录“下一步.txt”：模型、Bot ID、API Key、QQ 登录必须完成；健康检查不等于生图测试 |

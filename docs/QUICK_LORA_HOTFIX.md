# Quick 动态画风修复：0.5.0-beta.2-lora.1

修复懒人包九节点 `AAA_Quick_Local_api.json` 在选择画风时提示“未配置用于定位基础 MODEL/CLIP 的画风 LoRA 节点”。不用增加假槽位、不用重下模型、不必切换工作流。

## 已部署用户：推荐最小更新

1. 备份 AAA 插件目录及其配置/数据，等任务结束，正常退出 AstrBot（桌面版退出程序）。
2. 解压 `AAA_Quick_Lora_Hotfix_0.5.0-beta.2-lora.1.zip`，把原插件目录的 `preset_runtime.py` 单独复制到安全备份位置。
3. **只用包内 `preset_runtime.py` 替换运行实例的同名文件**，不要复制到 ComfyUI；不要覆盖 `data`、角色/画风预设、用户词库、令牌配置。
4. 重新启动 AstrBot。在 AAA 插件中保留原 `AAA_Quick_Local_api.json` 路径；画风加载模式设为 `dynamic`，画风 LoRA 槽位节点 ID 留空。
5. `/aimg_status` 仍显示 9 节点、0 LoRA、画风槽位无是正常的：新 LoRA 只在本次提交的内存图中生成。
6. 先选择已安装的一个画风、暂不选角色，普通生图一张；再添加角色验证。模型和预设里的文件名仍须与本机匹配。

Windows AstrBot Desktop 常见插件位置在 `%USERPROFILE%\.astrbot\data\plugins\astrbot_plugin_comfy_bridge`，但以实际运行实例的数据目录为准。不能用程序安装目录代替数据目录。
Linux 同样只替换真实插件目录下的文件。这个包不自动寻找或改写用户目录。

单文件补丁基于公开 beta.2 的运行模块。若用户自行改过 `preset_runtime.py`，请先比较，不要覆盖自定义修改；其它非 0.5 系列版本不承诺兼容。只替换运行模块不会改变旧 `metadata.yaml` 的版本显示，这不是未生效的证据；是否加载新模块以重启后的功能测试为准。
完整插件更新包的版本显示为 `0.5.0-beta.2-lora.1`；老用户优先用单文件补丁，避免完整安装包中的空示例库覆盖自定义文件。

## 新安装用户

选择名称带 `lora.1` 的 Windows / Linux 懒人包，已经包含修复插件和前次 `network.1` 下载修复。其它 Hub / App / 模型无需为这个问题更新。

## 旧四槽工作流

如果用户已经换用了 `AAA_Quick_4Slot_Compat_api.json`，继续使用真实的 `46,47,48,49` 即可，旧槽位模式不变；补丁不要求换回 Quick。
兼容工作流包只是备用方案，不含模型；作者模型/LoRA 文件名仍需要用户匹配，详见包内说明。

## 安全与边界

- 无 LoRA 图从采样器 MODEL 和正向编码 CLIP 接线定位，不写死基础模型节点编号。
- 正负 CLIP 不一致、接线无效、槽位只存在一部分、存在未配置 LoRA 等歧义会报错，不静默猜接线或叠加旧画风。
- fixed 模式仍必须使用真实 LoRA 槽位；dynamic 模式无 LoRA 图可留空，并兼容遗留但全部不存在的槽位编号。
- 不改变尺寸、种子、采样参数、模型文件或原始工作流文件；不改角色/画风定义。
- 自动测试不代替用户 GPU 真正出图。遇到模型名、架构不匹配等新错误，请保留新日志单独排查。

回退：退出 AstrBot，恢复备份的 `preset_runtime.py`，还原此前配置，再启动。无需删除任何模型或用户数据。

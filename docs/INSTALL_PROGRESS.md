# 安装进度与阶段状态

2026-10-23，`progress-candidate.1` 本地候选版。此功能在本次修订懒人包内，尚未上传替换 GitHub 附件。旧包不会自动获得此界面；已安装正常的用户无需为了查看进度重新安装后台。

完整解压对应系统懒人包，Windows 打开 `Deploy-Windows.cmd`，Linux 桌面打开 `Deploy-Linux.sh`，在安装与启动中心选择①部署环境。先预检，再确认部署。进度区固定在窗口上方，向下滚动表单后仍可见。

## 如何看状态灯

| 显示 | 表示什么 | 接下来做什么 |
| --- | --- | --- |
| 灰色「待执行」 | 尚未执行这一阶段 | 等待前面的步骤 |
| 蓝色「进行中」 | 当前正在执行 | 看当前任务、计时和日志 |
| 绿色「完成」 | 这一阶段已执行完毕 | 等待后续步骤 |
| 灰色「跳过」 | 复用原环境，或没有勾选对应安装项 | 正常情况 |
| 黄色「待处理」 | 检查已经结束，但部分服务还没就绪 | 看服务日志，处理后用「仅启动已有服务」 |
| 红色「失败」 | 当前安装操作已经中断 | 保存日志，修正原因，载入原计划重试 |

主部署共九个阶段：检查准备、应用环境、AAA 项目文件、Python 依赖、可选扩展、模型与工作流、连接配置与 AM、启动入口、服务健康检查。「已处理 X/9」包含按选项跳过的阶段。

只做预检、仅启动已有服务、旧版组件助手及仅补装扩展分别显示自己的阶段；这些入口保持原有安装范围。

## 进度条和等待时间

- 第一条显示已处理阶段的比例。各阶段耗时差异很大，不能据此推算剩余时间。
- 当前文件有固定大小时，第二条显示实际字节／总字节、百分比和下载平均速度，支持 `.part` 断点继续。
- 下载到 100% 后仍需校验。SHA256 校验按实际读盘进度显示，不代表服务已经可用。
- pip、Git、未知文件大小的操作显示滚动条。安装命令暂时没有输出时，约每 15 秒提示仍在运行。
- 窗口显示总用时、当前阶段用时、距最近输出的时间。时间在走表示界面仍在响应；下载速度为零或长时间无输出时结合日志判断。
- 下载保留原有连接／低速超时与有限重试机制，不取消超时或跳过哈希校验。

Windows 前置控制台也显示 Python／Git 检查和准备步骤，以及 winget 原始输出。这只表示启动器准备，进入部署向导后再查看九阶段状态。PowerShell 5.1 启动脚本保持 ASCII 编码。

## 如何确认安装结束

- 「完成」：本轮流程结束。首张图和 QQ 投递仍需按首次配置向导验收。
- 「流程结束，仍需配置」：文件／依赖部署或启动检查已结束。按日志及安装目录的 `下一步.txt` 完成模型、AstrBot Key、Bot ID、AM 或服务故障处理，不要反复重新部署。
- 「安装／启动失败」：当前失败阶段为红色，后续阶段保持待执行。用「保存安装日志」导出当前窗口输出；下次选择原 `last-plan.json` 载入表单并重新预检。

安装目录的 `deployment-status.json` 保留最后阶段、各灯状态及更新时间，供安装中心只读查看；它不是自动跳过检查的依据。服务日志仍为 `Hub.log`、`ComfyUI.log`、`AstrBot.log`。发给维护者前检查导出的日志，遮盖自行填写或第三方输出中的敏感信息。
